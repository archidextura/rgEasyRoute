# 덜 지치는 서울길 (ODsay 연동판)

ODsay LAB 대중교통 길찾기 API로 버스·지하철 조합을 받아와, 경로마다 칼로리(휴식 대비 추가 소모량)를 계산해 덜 힘든 순서로 정렬합니다.

## 실행 (3단계)

1. **Node.js 18 이상 설치**: `node --version`으로 확인합니다.
2. **키 넣기**: `.env.example`을 복사해 이름을 `.env`로 바꾸고, `=` 뒤에 키를 붙여 넣습니다.
   ```
   ODSAY_KEY=ODsay 서버 키
   TMAP_APP_KEY=TMAP 앱 키
   KAKAO_REST_KEY=(선택) 카카오 REST API 키
   ```
3. **서버 실행** 후 브라우저에서 http://localhost:8787 을 엽니다.
   ```bash
   node server.js
   ```
   터미널에 ✔/✘로 각 키가 인식됐는지 표시됩니다. 화면 위쪽 초록 배지로도 확인할 수 있습니다.

키가 없으면 그 기능만 빠지고 나머지는 동작합니다.
- ODsay 없음: 서울역 → 해방촌 데모 응답
- TMAP 없음: 지도 없음, 걷는 길은 직선 추정
- 장소 검색: 카카오 → TMAP → OpenStreetMap 순서로 있는 것을 씀

## 역 엘리베이터·에스컬레이터 넣기 (선택)

키 없이 파일 다운로드만으로 씁니다.

1. 공공데이터포털(data.go.kr)이나 서울 열린데이터광장에서 **"서울교통공사 엘리베이터"**, **"서울교통공사 에스컬레이터"**로 검색해 역별 설치 현황 CSV를 내려받습니다. 엘리베이터와 에스컬레이터 파일을 둘 다 받으세요.
2. 받은 파일을 `data/raw/` 폴더에 넣고 가져오기를 실행합니다.
   ```bash
   node tools/import-facilities.js
   ```
   파일마다 찾은 열과 구간 분류 결과가 출력됩니다. 열을 잘못 찾았으면 이 출력을 그대로 알려 주세요.
3. 서버를 다시 시작하면 화면의 "역 안 오르내리기"에 **역별 실제 시설**이 생기고 기본으로 선택됩니다.

판정 방식:
- 지하철을 탈 때와 내릴 때를 "지상↔대합실(7m)", "대합실↔승강장(8m)" 두 구간으로 나누고, 환승은 6m로 봅니다.
- 시설의 위치 문구에 "출입구·출구·지상"이 있으면 지상↔대합실, "승강장"이 있으면 대합실↔승강장, "환승"이 있으면 환승 시설로 분류합니다.
- 그 구간에 에스컬레이터가 있으면 에스컬레이터, 엘리베이터만 있으면 엘리베이터, 둘 다 없으면 **계단**으로 계산합니다.
- 데이터에 없는 역과 호선(예: 다른 운영사 노선)은 "정보 없음"으로 표시하고 에스컬레이터로 가정합니다.
- 도착역 지상 구간에 엘리베이터가 있으면 몇 번 출구 쪽인지 알려 줍니다.

주의할 점:
- 역 단위 데이터라서 "몇 번 출구가 계단뿐인지"까지는 구분하지 못합니다. 같은 역에 지상 에스컬레이터가 하나라도 있으면 그 출구를 쓴다고 가정합니다.
- 어떤 역의 시설이 데이터에서 일부 빠져 있으면, 실제로는 있는 구간도 계단으로 계산될 수 있습니다.

## 구조

| 파일 | 역할 |
|---|---|
| `server.js` | 정적 파일 제공 + API 중계. ODsay·카카오 키는 서버에만 있습니다. TMAP 키는 지도 스크립트에 들어가므로 브라우저에 보입니다. |
| `.env.example` | 키 입력 양식. `.env`로 복사해서 씁니다. |
| `public/index.html` | 화면, ODsay 응답 해석, 칼로리 계산 |
| `tools/import-facilities.js` | 역 시설 CSV → `data/station-facilities.json` 변환 |
| `fixtures/odsay-sample.json` | 데모 모드용 ODsay 형식 예시 응답 (가짜 데이터) |

서버가 중계하는 외부 API는 네 가지입니다.

- `/api/route`: ODsay `searchPubTransPathT` (대중교통 경로)
- `/api/geo`: 카카오 로컬 / TMAP POI / OpenStreetMap Nominatim (장소 이름 → 좌표)
- `/api/walk`: TMAP 보행자 경로 (실제 골목길 좌표)
- `/api/elev`: Open-Meteo Elevation (90m 격자 고도, 키 불필요)

## ODsay 응답을 구간으로 바꾸는 방식

- `trafficType` 1 = 지하철, 2 = 버스, 3 = 도보. 버스 `lane[0].type` 3이 **마을버스**입니다.
- 도보 구간의 시작·끝 좌표는 앞뒤 승차 구간의 `endX/endY`, `startX/startY`에서 가져옵니다. TMAP 보행자 경로(없으면 직선)를 따라 나눠 고도를 받고, 오르막·내리막을 따로 누적합니다.
- 지하철 승하차 때는 지상↔대합실 7m와 대합실↔승강장 8m, 지하철끼리 환승할 때는 6m를 오르내린다고 가정합니다. 역 시설 데이터가 있으면 구간마다 에스컬레이터·엘리베이터·계단을 판정합니다.
- 대기 시간(지하철 3분, 버스 5분, 마을버스 7분)과 서서 갈 확률은 가정값입니다.
- 직선거리 3km 이내면 "전부 걷기"(TMAP 보행자 경로, 없으면 직선거리 × 1.3)를 비교안으로 추가합니다. 700m 이내는 ODsay가 경로를 주지 않으므로(오류 코드 -98) 걷기만 보여 줍니다.

## 한계와 다음 단계

- 걷는 구간은 TMAP 보행자 경로를 50m 간격으로 다시 나눠 고도를 받습니다. 고도 데이터 자체가 90m 격자라 짧은 급경사는 덜 잡힐 수 있습니다.
- 역 깊이(7m + 8m)는 아직 모든 역에 같은 가정값입니다.
- 장소를 못 찾으면 지도에서 직접 고르거나 `37.55,126.97`처럼 좌표를 넣으세요.
- 검색 한 번에 TMAP 보행자 경로를 걷는 구간 수만큼(보통 5~15회) 호출합니다. 무료 호출량을 확인하세요.
- 이 코드는 아직 실제 ODsay·TMAP·카카오 키로 시험하지 않았습니다(가짜 응답으로만 시험). 오류가 나면 화면의 메시지를 알려 주세요.
